# 辞职后，我给升降桌做了一个网关

最近辞职在家，时间一下子多了起来。过去上班时攒下的那些小念头，也开始一个个从硬盘和备忘录里往外冒。这里面有一件事拖得最久：把我的升降桌改造成一张可以由电脑和手机控制的桌子。

这张桌子用了几年，机械部分一直没出过问题，控制方式却很传统。桌边挂着一块原厂面板，上面有上升、下降和四个档位键。平时调高度只能伸手去按，桌子也没有蓝牙、Wi-Fi 或智能家居接口。

我倒不是懒得伸这一下手。真正让我惦记的是，桌子已经有电机、控制盒和高度记忆，却始终被一块固定在桌边的面板拴着。键盘上有闲置的快捷键，桌面上也有旋钮，手机和手表更是随手就能碰到。只要能弄明白原厂面板发了什么指令，控制入口就不用局限在那几个塑料按键上。

这件事说起来轻巧，前后却走了不少弯路。我买了逻辑分析仪，拆了控制面板，用一块闲置的 ESP32-S3 模拟按键，后来又为了读取高度推翻了已经稳定的方案。现在桌子已经可以通过 Web、蓝牙、iPhone、键盘和旋钮控制，但它离我心里的“升降桌网关”还差几步。

## 一个搁了很久的念头

早些时候，我在少数派看过《[从零开始，改造一张可以用 Siri 控制的升降桌](https://sspai.com/prime/story/diy-a-siri-enabled-standing-desk)》。作者通过模拟控制面板按键，把一张普通升降桌接进了 HomeKit。后来我又找到了开源项目 [Upsy Desky](https://github.com/tjhorner/upsy-desky)，它把控制模块插在原厂面板和控制盒之间，再把升降桌接入家庭自动化系统。

方向已经有人走通了，可惜具体方案搬不过来。升降桌看起来大同小异，内部协议其实五花八门。Upsy Desky 主要适配使用双向 UART 通信的控制盒，我这张桌子的面板只有四根线，线上的数据也不是同一套东西。

最开始，我只是想复刻一个在 zFrontier 看到的[旋钮控制方案](https://www.zfrontier.com/app/flow/1b0Jwj5y6wOk)。桌面上原本就有一个旋钮，如果顺时针转是升高，逆时针转是降低，按下是停止，用起来会比摸索桌边的面板顺手得多。

真动手后，我的想法变了。旋钮只是入口之一。键盘快捷键可以控制，浏览器可以控制，手机和 Apple Watch 也可以控制。以后接入 Home Assistant，同样的升降指令还能进入自动化场景。事情一下子从“给桌子接个旋钮”变成了“给桌子留一个统一入口”。

问题也随之变得很直接：我得先听懂原厂面板在说什么。

## RJ45 里面只有四根线

原厂面板通过一个 RJ45 插头连接控制盒。这里的 RJ45 只是接口形状，不是以太网，更不能插进电脑网口试运气。

拆开面板后，电路板背面正好留着四个测试点：`3.3V`、`GND`、`CLK` 和 `DAT`。用万用表做导通测试后，线序也对上了：红线是 3.3V，白线是时钟，绿线接地，黑线传数据。

面板正面的主芯片是 TM1650。它同时负责数码管显示和按键扫描，常见于电磁炉、热水器之类的小家电。这个发现帮我缩小了范围，原先看起来毫无头绪的四根线，基本可以按一条类 I²C 总线来分析。

接逻辑分析仪之前，我先用万用表确认了工作电压。分析仪只接 `GND`、`CLK` 和 `DAT`，不接面板的 3.3V，也不向总线供电。原厂面板和控制盒保持正常连接，分析仪只是趴在旁边听。

最初的采样率设得太低，只能看到线上确实有脉冲，放大后却是一团乱麻。把采样率提高到 12 MHz 后，PulseView 才能稳定解出事务。静置、按住上升、按住下降、单击档位、长按保存档位，我把能想到的操作陆续录了一遍。短动作录几百毫秒，档位保存和全程升降则一次录八秒多。每个文件都记下当时的面板高度和手上做了什么，否则过几天再看波形，很容易张冠李戴。

## 控制盒一直在问，面板只负责回答

抓包后确认，控制盒是 I²C Master，负责产生时钟并发起通信；原厂面板里的 TM1650 是 Slave。它不会主动发一条“桌子上升”的命令，而是在控制盒轮询按键时回答当前键态。

静置时，控制盒大约每 3.7 毫秒问一次。没有人按键，面板返回 `0x2E`；按住上升时返回 `0x47`；按住下降时返回 `0x4F`。只要按着不放，面板就持续回答相同的值。松手后重新回到 `0x2E`，桌子随即停止。

目前确认的主要键码如下：

| 面板状态 | 返回值 |
| --- | --- |
| 没有按键 / 停止 | `0x2E` |
| 按住上升 | `0x47` |
| 按住下降 | `0x4F` |
| 单击档位 1 | `0x17` |
| 长按保存档位 1 | `0x57` |
| 单击档位 4 | `0x2F` |
| 长按保存档位 4 | `0x6F` |

档位 2 和档位 3 当时没有留下可靠抓包，我也没有根据相邻数值去猜。让一张桌子动起来的代码，宁可少支持两个按钮，也不能拿未经验证的键码碰运气。

高度走的是另一条逻辑通道。控制盒知道当前高度，并把数字转换成数码管段码，写到 `0x34` 至 `0x37` 四个地址。也就是说，按键和高度共用同一对 `CLK/DAT`，只是通过不同地址分工。键通道是控制盒读取面板，高度通道是控制盒刷新面板上的数码管。

这也解释了我早期的一个误判。我曾经把运动时出现的显示地址当成电机干扰，认为高度不在这条总线上。后来对照 TM1650 的资料，又拿 64 cm、102 cm 等静止高度的抓包反复比对，才发现那些被我扔掉的数据正是数码管内容。回过头看，这个错误有点灯下黑：芯片型号已经印在面板上，我却先入为主地盯着按键返回值找高度。

## 用 ESP32-S3 顶替原厂面板

协议摸清后，下一步是让 ESP32-S3 假装成原厂面板。

这一步的工作方式和直觉不太一样。ESP32-S3 不需要主动向控制盒发送一串升降命令，而是作为地址 `0x24` 的 I²C Slave 等着。控制盒来读时，ESP32-S3 根据当前控制意图返回一个字节。Web 页面按住“上升”，返回值变成 `0x47`；松手或点击停止，立即恢复 `0x2E`。

我用 USB-C 给 ESP32-S3 独立供电，只把地线、时钟线和数据线接到控制盒。第一次测试时，串口日志看着一切正常：点上升时当前键码变成 `0x47`，点下降时变成 `0x4F`。桌子却纹丝不动。

这类故障很容易把人带进软件里。日志说“我要返回 `0x47`”，只能证明内存里的变量变了，不能证明控制盒在电线上收到了这个字节。我重新测量原厂面板后发现，面板上还藏着两只约 2 kΩ 的上拉电阻，分别把 `CLK` 和 `DAT` 拉到 3.3V。拔掉面板时，这两只电阻也跟着没了。

补回两个上拉电阻后，桌子终于动了。按住 Web 页面里的上升按钮，桌子连续升高；松手，停止；按住下降，桌子再平稳降下来。折腾了几天，真正看到桌腿开始移动的那一刻，反而没有什么仪式感。我只是赶紧又按了几次停止，确认它每次都能停住。

## 高度读取把事情带进了岔路

升降和停止稳定后，我自然想把原厂面板上的高度也读出来。协议已经分析清楚，段码表也能还原 64、82、102、121 这些高度，看起来只差把解析代码塞进固件。

麻烦出在硬件外设上。

ESP32-S3 有两组硬件 I²C 控制器，但这里需要在同一组 `CLK/DAT` 上处理五个从机地址：`0x24` 是按键，`0x34` 至 `0x37` 是四个数码管位置。一个硬件 I²C Slave 只能配置一个精确地址，两组控制器也覆盖不了五个地址。这里说的“五个”是同一条总线上的五个地址，不是五组物理 I²C 接口。

为了同时回答按键轮询并接收高度段码，我把这部分改成了软件 I²C。GPIO 中断逐个读取 SCL、SDA 的边沿，程序自己判断 START、STOP、地址、数据和 ACK，需要应答时再决定什么时候拉低 DAT。

高度很快显示出来了，但原本流畅的上升开始断断续续。桌子升一下、停一下，再升一下，像有人在不断松开和按下按钮。下降起初还算正常，继续修补时序后也出现了相同问题。

我先后排查了 Web 页面是不是提前发送 STOP、BLE 的长按租约是否过期、高度刷新是否触发了安全上限。都不是。日志里没有出现代表停止的 `0x2E`，桌子依旧会停，说明控制盒压根没有完整读到每一次 `0x47`。

后来加了更细的诊断计数，问题一下子露了出来。三段测试共发起 394 次按键响应，只有 20 次完整发送，另外 374 次在中途被打断，完成率只有大约 5%。控制盒偶尔读到一次完整的 `0x47`，桌子就开始上升；下一轮读取失败，它又把这当成按键没有继续按住。

软件模拟不稳定并不是 ESP32-S3 算力不够。Wi-Fi、BLE、日志、任务调度和 GPIO 自身的边沿都会挤进来，实时性已经从专用硬件外设转移到了软件中断。为了一项高度数据，我改写了已经稳定的运动链路，多少有些舍本逐末。

我最后停止继续修补软件 I²C，把控制盒侧恢复成硬件 I²C Slave。它只应答 `0x24`，上升、下降和停止重新交给硬件处理。高度字段暂时返回未知，Web、手机和 Watch 上显示一条横线，不用模拟值冒充真实高度。

新的方案是在桌板下方安装一颗 TOF200C 测距模块，测量传感器到地面的距离，再加上固定安装偏移，换算出桌面高度。ESP32-S3 的另一组硬件 I²C 作为 Master，专门连接测距模块。这样运动控制和高度采集各走各的，互不搅扰。

这颗传感器目前还没有完成采购和真机验证。后面需要测试 64 至 129 cm 全行程，还要看深色地面、地垫、环境光和遮挡会不会影响读数。在这些测试做完之前，它只是一条已经选定的路，还不能算完成。

## 控制入口开始多了起来

底层的升降指令收进统一控制层后，增加入口就轻松多了。它们不需要各自理解 TM1650，也不能绕过停止、童锁和超时规则，最后都落到同一组上升、下降和停止动作。

目前最直接的是局域网 Web 页面。ESP32-S3 连上家里的 2.4 GHz Wi-Fi 后，可以在浏览器里打开控制页。按住按钮时桌子运动，松手后停止。Web 还会显示连接状态、童锁、控制来源开关和固件信息。页面只应该留在局域网里，我没有把它映射到公网。

iPhone App 默认优先走 BLE，蓝牙不可用时可以切到局域网 REST。BLE 做了短租约：手机需要持续续期才能保持运动，松手、断连或 App 退出都会触发停止。这个设计稍显啰嗦，却比发出一次“开始上升”后等客户端再补一条“停止”稳妥。

键盘和旋钮走的是另一条很朴素的路径。Karabiner 把旋钮的顺时针、逆时针和按下映射到 `F18`、`F17`、`F16`，Shell 脚本再调用 ESP32-S3 的 REST 接口。为了避免误碰一个刻度就让桌子窜动，第一个刻度只进入待命，700 毫秒内出现第二个同方向刻度才开始运动。停止旋转后，最后一个刻度留下的运动租约会在大约 500 毫秒后到期。运动中反向旋转时，先停，再等第二个反向刻度启动新方向。

Apple Watch 的原型也已经做出来。Digital Crown 顺时针对应上升，逆时针对应下降，停止旋转后由 Watch 和 ESP32-S3 两层超时共同兜底。Watch App 的代码、单元测试和通用构建已经完成，真机扫描、配对、Crown 停止以及与 iPhone、Android 的三设备并发还没有全部验收。现在把它写成“已经能稳定控制桌子”还为时过早。

语音控制也可以复用同一个 REST 入口。现阶段我更愿意先把手动升降和停止做稳。固定坐姿、站姿依赖可靠高度，TOF200C 没有通过全行程测试前，语音直接前往某个高度仍然处于停用状态。

## 我想要的最终形态是双 RJ45 网关

目前这版 ESP32-S3 仍然属于“替换面板”验证。它证明了协议可以复现，也确实能控制我的桌子，但原厂面板拔掉后就不能用了。日常使用显然不能一直拖着开发板，更不该为了增加手机控制，反而丢掉最可靠的实体按键。

最终的 Desk Gateway 会有两个 RJ45 接口。在我的设计里，北向连接原厂控制盒，南向连接原厂面板。网关夹在中间，平时透明转发双方数据，原厂面板的显示和按键都照常工作。手机、Web 或旋钮发来指令时，网关再向控制盒注入等价键态。

夹在中间以后，童锁才算真正闭环。现在的童锁可以拦住 Web、REST 和 BLE，却挡不住直接连在控制盒上的原厂面板。双 RJ45 网关能在童锁开启时丢弃面板的升降意图，同时保留 STOP。原厂面板按键与无线命令冲突时，也可以让实体面板优先。

这部分还没有完成。两侧 GPIO、供电连通和上拉电阻已经测过，但原厂面板一侧还缺一份可靠的全上电抓包，透明透传、按键仲裁和数码管刷新都要在真桌上继续验证。面包板和新的抓包接线准备好之前，我不打算凭旧波形硬写下去。

## 从适配一张桌子开始

回头看 Upsy Desky，我现在最想借鉴的已经不是某一段协议代码，而是它的产品位置：让网关处理连接和自动化，把不同桌子的差异留在协议适配层。

我给这个适配层起名叫 Desk Driver。现在真正实现的是自己的 `yourdesk_v1`，Loctek、Jiecang 等桌型还只是占位。以后遇到使用 UART 的桌子，可以参考 Upsy Desky 的接入方式；遇到和我这张桌子一样使用 TM1650 或其他面板芯片的桌子，就重新抓包、整理键码，再写一个对应 Driver。Web、手机、Watch、BLE 配对和童锁不用跟着推倒重来。

硬件也会继续收拾。眼下的开发板、杜邦线和外接电阻适合验证，不适合长期挂在桌子下面。我还没正经画过一块能投入使用的 PCB，接下来准备先把双 RJ45、USB-C 供电、ESP32-S3 最小系统、上拉和保护电路整理到一张原理图上，再做一块简化板。第一版大概率不会漂亮，能正常焊接、方便测量、留足测试点就算达到目的。

如果后面的桌型适配和 PCB 都能按部就班地推进，这个项目才有机会从自用工具变成一个小产品。眼下没有必要急着谈量产。原厂面板透传、独立高度、异常停止和真实硬件验收，哪一项都比外壳和包装更要紧。

## 现在，它已经是我每天能用的桌子了

这次改造还没有到收工的时候。硬件 I²C 的稳定基线已经完成手动升高、降低和停止验证，Web、BLE、iPhone、键盘和旋钮也分别在真实桌子上跑过。最近把整合固件从软件 I²C 切回硬件 I²C 后，我还要重新烧录并复验这些入口，不能拿不同阶段的成功记录拼成一句“最终版已经完成”。高度暂时未知，Apple Watch 等真机验收，双 RJ45 和更多桌型则排在后面。

辞职后重新捡起这个旧坑，我原本只想给桌边添一个旋钮。现在桌子下面多了一块 ESP32-S3，硬盘里多了许多抓包文件，项目里还排着测距、透传和 PCB。事情绕了一大圈，好在没有原地踏步。

下一步先把 TOF200C 装到桌板下面，用卷尺做完整标定。再往后，我会重新接好原厂面板一侧的逻辑分析仪，把双 RJ45 透传这块硬骨头啃下来。等这些都稳定了，再考虑 Home Assistant、Siri 和更多型号。

现在我转一下桌上的旋钮，桌子会升起来；手停下，它也会停。这已经比最初那张只能摸着面板操作的桌子顺手不少。
