## 1. 当前方案

| 安装位置 | 模块 / 芯片 | 当前用途 | 产品数据 |
|---|---|---|---|
| 桌面右侧，水平朝向右侧障碍物 | TOF050C / VL6180X | 测量桌面右侧间距，参与低位上升保护 | `right_gap_mm` |
| 桌板下方，垂直朝向地面 | TOF400C / VL53L1X | 直接作为桌面高度，参与档位闭环和最高高度保护 | `height_mm` / `tof_height_mm` |

两块模块的接口丝印相同，均为 `VIN/GND/SDA/SCL/INT/SHUT`。TOF400C 模块正面标注
`TOF400C-VL53L1X`；固件还会读取芯片 ID，TOF050C 期望 `0xB4`，TOF400C 期望 `0xEACC`。

当前高度不做卷尺高度换算，也不叠加安装偏移。用户实测参考关系为：

| TOF400C 读数 | 卷尺参考高度 | 用途 |
|---:|---:|---|
| 约 `56 cm` | 约 `71 cm` | 坐姿档位 |
| 约 `87 cm` | 约 `105 cm` | 站姿档位 |
| `94 cm` | — | 允许配置的最高传感器高度 |

因此 Web、OLED、REST、BLE 和原厂面板显示的“高度”均采用处理后的传感器距离，不代表卷尺量得的桌面上表面高度。
表中的 `56 cm` 是早期实测关系记录，不是当前配置默认值；当前最低档位和坐姿档位默认值均为 `550 mm`。

## 2. GPIO 与接线

两颗 ToF 与 0.91 英寸 OLED 共用 I²C1：

| ESP32-S3 | TOF050C | TOF400C | OLED | 说明 |
|---|---|---|---|---|
| `3V3` | `VIN` | `VIN` | `VCC` | 使用开发板 3.3V |
| `GND` | `GND` | `GND` | `GND` | 所有设备共地 |
| `GPIO10` | `SCL` | `SCL` | `SCL` | I²C1 SCL，400 kHz |
| `GPIO11` | `SDA` | `SDA` | `SDA` | I²C1 SDA，400 kHz |
| `GPIO12` | `SHUT` | — | — | TOF050C 独立启停和改址 |
| `GPIO13` | — | `SHUT` | — | TOF400C 独立启停 |
| 不接 | `INT` | `INT` | — | 当前固件使用轮询，不使用中断 |

供电和总线约束：

- 两颗 ToF 使用 ESP32 开发板的 `3V3/GND`，不得接升降桌 RJ45 红线的 3.3V。
- ESP32、传感器、OLED 和外接 5V 电源必须共地。
- 两块模块的 I²C 上拉会并联；新增或更换模块后应断电检查 `SCL/SDA` 到 `3V3` 的等效阻值。
- OLED 地址自动探测 `0x3C` 和 `0x3D`，不会与 ToF 运行地址冲突。

相关 GPIO 已占用情况：

| GPIO | 当前用途 / 约束 |
|---|---|
| GPIO4 / GPIO5 | 控制盒侧 CLK / DAT |
| GPIO6 / GPIO7 | 原厂控制面板侧 CLK / DAT |
| GPIO19 / GPIO20 | ESP32-S3 原生 USB |
| GPIO35 / GPIO36 / GPIO37 | N16R8 Flash / Octal PSRAM 内部占用，禁止外接 |
| GPIO43 / GPIO44 | UART0 调试 |
| GPIO48 | 板载 WS2812 RGB |

## 3. 地址与启动顺序

VL6180X 和 VL53L1X 的默认 7-bit I²C 地址均为 `0x29`，必须通过两根独立 `SHUT` 线消除冲突。
固件每次启动都执行：

1. GPIO12、GPIO13 同时拉低，关闭两颗传感器。
2. 释放 GPIO12，只启动 TOF050C。
3. 在默认地址 `0x29` 校验 VL6180X Model ID `0xB4`，然后把运行地址改为 `0x30`。
4. 释放 GPIO13，启动 TOF400C。
5. 在默认地址 `0x29` 校验 VL53L1X Sensor ID `0xEACC`。
6. 后续分别从 TOF050C `0x30` 和 TOF400C `0x29` 轮询数据。

地址修改不会跨掉电保存，因此每次启动都必须重新执行。任一传感器初始化失败时，对应数据保持未知，
不能用 `0`、旧缓存或模拟值替代。

## 4. 采样与防抖

### 4.1 TOF050C

- VL6180X 使用 1 mm 量程缩放，约 10 Hz 轮询。
- 只有量程状态有效的样本进入滤波器。
- `CONFIG_DESK_TOF_RIGHT_OFFSET_MM` 可补偿水平安装偏差，默认 `0 mm`，配置范围 `-200～200 mm`。
- `INT` 和 ALS 当前均未使用。

### 4.2 TOF400C

- VL53L1X 使用 Long Distance Mode、`100 ms` timing budget。
- ROI 使用完整 `16 × 16` 感光区域，优先保证朝向地面的稳定性。
- 只有 `range_status == 0` 的样本进入滤波器。
- 滤波后的原始距离直接作为产品高度，不做比例换算或安装偏移校准。

### 4.3 共用稳定滤波器

两路传感器使用相同的稳定滤波逻辑：

1. 启动阶段少于 5 个有效样本时，直接采用最新有效值，避免长时间无数据显示。
2. 收满 5 个有效样本后，使用 5 点中值过滤单帧毛刺。
3. 新中值与当前输出相差不足 `3 mm` 时保持原值，形成 `3 mm` 死区，减少小数点附近反复跳动。
4. 超过 `1000 ms` 没有新有效样本时，对应 `*_known` 变为 `false`，数值对外返回未知。

该逻辑解决稳定显示和单帧异常问题，不用于掩盖持续遮挡、掉线或无效量程状态。

## 5. 数据流与显示

```text
TOF400C / VL53L1X ── 有效性检查 ── 5 点中值 + 3 mm 死区 ── height_mm
                                                               ├─ desk_core 运动裁决
                                                               ├─ REST / Web / BLE
                                                               ├─ OLED
                                                               └─ 原厂面板数码管

TOF050C / VL6180X ── 有效性检查 ── 5 点中值 + 3 mm 死区 ── right_gap_mm
                                                                  ├─ 上升安全裁决
                                                                  ├─ REST / Web
                                                                  └─ OLED
```

REST 状态包含：

| 字段 | 含义 |
|---|---|
| `height_mm` / `height_known` | `desk_core` 当前高度；产品固件中由 TOF400C 提供 |
| `tof_height_mm` / `tof_height_known` | ToF 采集快照，用于明确传感器状态 |
| `right_gap_mm` / `right_gap_known` | 桌面右侧到障碍物的距离与有效标志 |
| `upward_blocked` | 当前是否因 ToF 安全策略禁止上升 |
| `preset1_mm` / `preset4_mm` / `max_height_mm` | 坐姿、站姿和最高高度设置 |

原厂面板只支持厘米数码显示，固件把 TOF400C 的毫米值四舍五入为厘米后发送给面板。

## 6. 档位与上升限制

默认配置：

| 配置 | 默认值 | 允许范围 / 约束 |
|---|---:|---|
| 最低档位高度 `min_height_mm` | `550 mm` | `550 ≤ min_height ≤ preset1`；不触发下行 STOP |
| 坐姿档位 `preset1_mm` | `550 mm` | `min_height ≤ preset1 < preset4` |
| 站姿档位 `preset4_mm` | `870 mm` | `preset1 < preset4 ≤ 940` |
| 最高高度 `max_height_mm` | `940 mm` | `min_height～940 mm` |
| 档位停止容差 | `5 mm` | 到达目标附近即停止 |

最低档位高度、档位和最高高度可由 Web 修改并保存到 NVS。最低档位高度只用于输入校验，
不会根据 TOF 跳动主动停止下降；机械最低位由控制盒处理。当前上升裁决矩阵如下：

| 当前状态 | 是否允许继续上升 | 原因 |
|---|---|---|
| 高度未知 | 否 | 无法证明未超过最高高度 |
| 高度 `≥ max_height_mm` | 否 | 达到最高高度 |
| 高度 `< 800 mm`，右侧距离未知 | 否 | 低位阶段无法证明右侧无障碍物 |
| 高度 `< 800 mm`，右侧距离 `< 80 mm` | 否 | 右侧障碍物过近 |
| 高度 `< 800 mm`，右侧距离 `≥ 80 mm` | 是 | 同时满足高度和侧距条件 |
| 高度 `≥ 800 mm` 且低于最高高度 | 是 | 此高度段不再使用右侧距离限制 |

边界值是严格按代码执行：高度达到 `800 mm` 后忽略右侧距离；右侧距离等于 `80 mm` 不拦截。
该策略避免把桌面升高后正常出现的 `7.x cm` 侧距变化误判为障碍物，同时由 TOF400C 的
`940 mm` 最高高度继续保护上升行程。

安全行为：

- Web、REST、BLE 和原厂面板发起上升前都会执行同一裁决。
- 运动期间每 `50 ms` 复查 ToF；条件变为不安全时立即发送 STOP。
- 档位运动过程中高度失效会立即停止，不继续盲走。
- ToF 上升保护不禁止下降和 STOP；发生误判或传感器故障时仍可下降脱离。
- 上升不再使用通用固定时长截止；真正的停止条件是松手、显式 STOP、来源租约、档位目标或 ToF 安全限制。

### 7.3 档位与安全矩阵

- [x] 从不同起始高度执行坐姿 `550 mm` 和站姿 `870 mm`，确认在 `±5 mm` 范围停止。
