| 项 | 内容 |

| 版本 | 1.0 |

本文汇总当前代码状态和用户真机验证结果。协议细节、接线步骤和分层设计仍分别以
[协议逆向笔记](./3-protocol-reverse-notes.md)、[真机验收清单](./bringup-checklist.md)和
[架构总览](./architecture/overview.md)为准。

## 1. 状态定义

| 状态 | 含义 |
|---|---|
| ✅ 已完成 | 代码已实现，核心路径已经在当前升降桌或 iPhone 上验证 |
| 🟡 待验收 | 代码已实现或主体已完成，但缺少完整真机、异常或跨平台验证 |
| ⬜ 未实现 | 只有方案文档、接口占位或尚未开始开发 |
| ⛔ 外部阻塞 | 继续工作依赖待到货硬件、抓包或第三方条件 |

“已完成”不代表所有异常场景都已经覆盖。安全相关边界仍必须按
[真机验收清单](./bringup-checklist.md)逐项复验。

## 2. 已完成

### 2.1 固件与桌子控制

- [x] ESP32-S3 主固件可在 ESP-IDF 6.0.2 下构建、烧录和启动。
- [x] `yourdesk_v1` 软件多地址 I²C Slave 同时响应键通道 `0x24` 和高度通道
  `0x34–0x37`。
- [x] Web 按住上升、按住下降、松手停止和独立 STOP 已通过真桌验证。
- [x] 档位 1 / 档位 4 已按真实高度闭环运行。
- [x] TM1650 真实高度已接入，Web、REST、BLE 和手机 App 使用同一高度状态。
- [x] 厘米/英寸显示模式的控制盒帧可以兼容解析，不再依赖模拟高度。
- [x] 最高安全高度已在固件中持久化，并可由 Web 和手机 App 配置。
- [x] 档位 1 / 4 高度已在固件中持久化，并可由 Web 和手机 App 配置和同步。
- [x] 全局童锁和 REST / Bluetooth / Panel 来源权限已经进入统一 `desk_core` 策略。
- [x] Web 可显示固件构建时间，并可请求 ESP32 重启。

### 2.2 BLE、手机和桌面自动化

- [x] NimBLE GATT Server、加密 Write、状态 Notify、HOLD 短租约和断连停止已实现。
- [x] LightBlue 已完成连接、状态读取和升降/STOP/档位 1/4 的核心真机操作。
- [x] React Native + Expo Development Build 的 iPhone App 已完成 Home / Settings 正式 UI。
- [x] iPhone App 已通过 BLE 控制真实升降桌。
- [x] 手机 App 已实现 BLE 优先、REST 回退、统一状态和设备配置读写。
- [x] 手机 App 已支持长按升降、STOP、档位、童锁、安全高度、档位高度和震动反馈。
- [x] Shell 脚本已支持档位 1、档位 4、上升、下降和停止。
- [x] GoatRemote 可以通过 Shell 命令控制档位 1 / 4。

## 4. 尚未实现

### P0：完成现有硬件产品闭环

1. **双 RJ45 原厂面板透传。** 主动事务透传和仲裁代码已有，但原厂面板按键仍无有效日志，
   尚不能作为可用功能交付。
2. **原厂面板优先仲裁。** 面板按键应能覆盖正在执行的无线运动命令。
3. **童锁真正屏蔽原厂面板。** 童锁和 Panel 权限必须在物理面板路径上完成真机验证。
4. **原厂面板高度显示透传。** 原面板数码管需要继续显示控制盒返回的真实高度。

当前阻塞：需要面包板和可靠的全上电逻辑分析仪抓包。抓包与接线按
[真机验收清单 B.4](./bringup-checklist.md#b4-phase-2-双口-rj45-透传接线)执行。

### P1：完成跨平台和安全验收

1. Android 真机技术验证与正式 UI 验收。
2. BLE / Wi-Fi 自动回退、权限拒绝、断连和恢复矩阵。
3. 固件与 App 的异常停止、重启、掉电和后台安全测试。
4. TestFlight / Android 内测打包和发布文档。

### P2：已设计的新硬件与客户端

1. **Apple Watch App：** 已冻结 SwiftUI + CoreBluetooth 直连方案，尚未创建 watchOS
   Target；见 [Apple Watch 控制方案](./architecture/apple-watch-control.md)。
2. **双 ToF 传感器：** TOF050C + TOF400C 的接线、地址和安全边界已设计，硬件未采购，
   驱动未实现；见 [双 ToF 接入方案](./4-tof-distance-sensor-plan.md)。

### P3：生态和扩展能力

1. MQTT + Home Assistant。
2. Matter、Siri / App Intent 和米家/华为生态接入。
3. OTA 固件升级。
4. Loctek、Jiecang 等其他桌型 Driver。
5. 原厂档位 2 / 3 协议逆向与实现。
6. 原厂“上+下约 5 秒重置”键码抓包与等价操作。
7. BLE OLED / 独立旋钮参考配件。

## 5. 推荐执行顺序

1. 面包板到货后先完成 P0 原厂面板抓包、透传、仲裁和童锁真屏蔽。
2. 等待硬件期间完成 P0 异常停止矩阵和 P1 Android 真机验证。
3. 完成 BLE / Wi-Fi 双通道回退验收及移动端内测打包。
4. 在 Apple Watch 与 ToF 中选择一个进入 P2 实施，避免同时扩展两条硬件链路。
5. P3 生态功能在现有控制闭环稳定后单独立项。

## 6. 文档维护规则

- 新功能只有在代码完成且核心真机路径通过后，才能从“待验收”移动到“已完成”。
- 仅通过编译、单元测试或模拟器不能替代桌子、手机或传感器真机验收。
- 任务优先级发生变化时先更新本文，再同步 README 和架构总览摘要。
- 详细测试证据写入 `bringup-checklist.md`，本文只保留结论和下一步。
