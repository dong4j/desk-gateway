# 代码提交规范

## 适用范围

本规范适用于 Desk Gateway 仓库中由 AI Agent 完成的所有本地 Git 提交，包括功能开发、缺陷修复、测试、文档、构建配置和工程维护。

## 基本原则

1. 每个可独立验证的小功能必须单独提交，禁止把多个无关功能合并到同一个提交。
2. 提交内容必须与提交信息准确对应，不得夹带格式化、重构或其他无关修改。
3. 提交前必须检查代码实现、相关文档、checklist、工程进度和测试是否需要同步。
4. 只允许暂存当前任务涉及的文件，必须保留用户或其他任务产生的无关工作区修改。
5. 未经用户明确授权，禁止 push、创建远程分支、创建 Pull Request 或修改远程仓库状态。
6. 未经用户明确授权，禁止使用 rebase、filter-branch、reset 或其他方式重写已有提交历史。

## 提交信息格式

提交信息统一使用 Conventional Commits 格式：

```text
type(scope): 中文描述
```

要求：

- `type` 使用小写英文，表示变更类型。
- `scope` 使用小写英文，表示主要影响范围；无法准确归类的仓库级变更可以省略 scope。
- 描述使用简洁、明确的中文动宾结构，直接说明本次提交完成的内容。
- BLE、I2C、REST、ESP-IDF 等技术名称保留原文，不强制翻译。
- 标题末尾不添加句号，不使用“更新代码”“修改问题”等含义模糊的描述。
- 单行标题应准确覆盖提交内容；确有必要时，可在空行后补充正文说明原因、约束或验证结果。

## type 取值

| type | 用途 |
| --- | --- |
| `feat` | 新增用户可见功能或工程能力 |
| `fix` | 修复缺陷或错误行为 |
| `docs` | 仅修改文档 |
| `test` | 新增或调整测试 |
| `refactor` | 不改变外部行为的代码重构 |
| `perf` | 性能优化 |
| `build` | 构建系统或依赖调整 |
| `ci` | CI 配置或自动化流程调整 |
| `chore` | 不属于以上类型的工程维护 |

## scope 取值

优先复用以下项目范围：

| scope | 适用内容 |
| --- | --- |
| `firmware` | ESP32 固件与硬件控制逻辑 |
| `ble` | BLE 协议、配对、连接和 Bond 管理文档或跨端契约 |
| `web` | Web 管理界面与前端逻辑 |
| `mobile` | 手机端应用与客户端逻辑 |
| `watch` | Apple Watch 应用与客户端逻辑 |
| `review` | 审查报告及审查流程材料 |
| `scripts` | 项目脚本与命令行工具 |
| `standards` | 项目开发规范 |

确需新增 scope 时，应使用能够长期复用且含义明确的小写英文名称，禁止为单次任务创建过细的 scope。

## 正确示例

```text
feat(firmware): 实现 BLE 三客户端并发控制
fix(mobile): 修复蓝牙设备管理状态门禁
docs(ble): 同步多客户端技术文档
test(firmware): 补充绑定设备删除失败测试
docs(standards): 新增 AI Agent 代码提交规范
```

## 错误示例

```text
实现 BLE 三客户端并发控制
update code
fix: 修复问题
feat(mobile): 修改一些代码。
```

以上提交分别缺少 Conventional Commits 前缀、没有中文准确描述、描述过于模糊或使用了不必要的句号。

## 提交前检查

每次提交前必须依次确认：

1. `git status --short` 中不存在误暂存文件。
2. `git diff --cached` 仅包含本次小功能需要的变更。
3. 相关代码、文档、checklist 和工程进度已经同步。
4. 与本次变更相关的测试或静态检查已经执行并通过；无法执行的验证必须如实记录，不能表述为已通过。
5. 提交信息符合 `type(scope): 中文描述` 格式并准确描述暂存内容。

提交完成后必须再次检查工作区状态，确认没有遗漏本次任务文件，也没有误处理无关修改。
