本文是 Desk Gateway V1 的最终验收入口。代码实现、自动化测试、固件启动和真机验收必须
分别记录；编译或单元测试通过不能替代桌体运动、BLE 射频、传感器和异常停止验收。

测试运动时必须有人站在桌旁，确保随时可以发送 STOP 或切断控制盒电源。测试人员不得在
桌下、桌面上方或运动路径内放置身体、线材和易损物品。

---

## 1. 验收状态

每个任务只能使用以下状态：

| 状态 | 含义 |
|---|---|
| `未执行` | 尚未开始，不能计入完成 |
| `通过` | 按本文步骤执行，预期结果全部满足且证据已保存 |
| `失败` | 已执行但存在不符合项，修复后必须完整回归 |
| `阻塞` | 缺少设备、环境或外部条件，仍视为未通过 |
| `不纳入 V1` | 仅用于第 5 节可选能力，已由发布负责人明确排除 |

V1 发布判定：

- P0、P1 任一任务不是 `通过`，结论必须为 **NO-GO**。
- P2 能力如果包含在 V1 发布说明中，对应任务必须为 `通过`；否则必须标记为`不纳入 V1`。
- P3 能力不属于 V1，不得因已有方案文档而写入 V1 已交付能力。
- 发现运动无法停止、误启动、权限绕过或传感器失效后继续盲走，立即停止整轮验收并判定
  **NO-GO**。

## 3. P0：核心桌控与安全门禁

以下任务按顺序执行。前一项失败时，先修复并重新验收，不继续扩大运动测试范围。

### V1-01 当前 App BLE 长按真桌回归

**目标：** 关闭此前“点击有反馈但桌子不移动”的问题，证明当前 App 和固件组合可用。

- [x] Web 按住上升、下降可持续运动，松手立即停止。
- [x] REST 上升、下降和 STOP 使用同一稳定硬件 I2C `@0x24` 路径。
- [x] App 明确处于 BLE 连接时，按住上升、下降可持续运动，松手立即 STOP。
- [x] App 震动或声音反馈不能替代真实运动结果。
- [x] 串口能区分命令接收、运动接受、拒绝和 STOP，测试中无非预期中断。

完成条件：Web、REST、BLE 三个入口在当前版本全部通过；只验证 Wi-Fi 回退不能关闭本项。

### V1-02 550 mm 最低高度跨端回归

- [x] Web 和 App 可保存 `min_height_mm=550`、`preset1_height_mm=550`。
- [x] REST 状态、BLE Config v3、Web、App 和 Watch 显示一致。
- [x] Gateway 重启后 NVS 中的最低高度和档位保持不变。
- [x] 档位 1 从不同起点闭环到达 `550 ±5 mm`。
- [x] 手动下降到机械最低位时，Gateway 不因 `min_height_mm` 或高度读数跳动主动发送 STOP。
- [x] 低于配置范围的档位写入被拒绝，但下降和 STOP 始终可用。

### V1-03 异常停止安全矩阵

- [x] 松手和显式 STOP 均能立即停止上升、下降和档位运动。
- [x] BLE 运动所有者断连、App 被杀或失联后在安全时限内停止。
- [x] 非所有者断连不影响当前所有者运动。
- [x] 网络断开、BLE/Wi-Fi 切换和请求超时不会重放旧运动命令。
- [x] 下降约 15 秒超时停止；上升仍由松手、STOP、来源租约或 ToF 闭环停止。
- [x] ESP32 重启、控制盒掉电和恢复后不会自行继续上次运动。
- [x] 童锁开启、来源权限关闭和 Bond 删除前均先停止当前运动。

每个异常场景必须保存串口时间线和对应客户端状态，不能只记录“桌子停了”。

### V1-04 双 ToF 档位与上升安全矩阵

详细步骤以[双 ToF 距离传感器接入与安全策略](../architecture/tof-safety.md)第 7 节为准。

- [x] 连续冷启动 20 次，两颗 ToF 地址、采样和 OLED 共存稳定。
- [x] 550 / 870 mm 档位和 940 mm 最高高度闭环停止。
- [x] 高度低于 800 mm 时，右侧距离未知或小于 80 mm 会停止并禁止上升。
- [x] 高度达到 800 mm 后，右侧 `7.x cm` 读数不会误停，940 mm 上限仍生效。
- [x] 运动中断开 TOF050C、TOF400C 后执行符合安全策略。
- [x] 暗光、室内照明、浅色/深色地面和地垫下无不可接受的漂移或长时间未知。
- [x] Web、BLE 和原厂面板执行相同裁决；下降和 STOP 始终可用。

### V1-05 原厂面板代理与童锁

详细接线以[真机验收清单 B.4](../guides/bringup-checklist.md#b4-phase-2-双口-rj45-透传接线)为准。

- [x] 原厂面板短按/按住上升、下降和松手停止正常。
- [x] 面板显示与 TOF400C 四舍五入后的厘米高度一致。
- [x] 面板运动期间拔掉右侧 RJ45，桌子立即停止。
- [x] 面板控制期间 Web/BLE 冲突运动请求被拒绝，松手后恢复。
- [x] 童锁开启或 Panel 来源关闭后，面板不能启动运动，STOP 仍有效。
- [x] 重新允许 Panel 时，持续按住的旧按键不会直接恢复运动，必须松开后重新按下。

### V1-06 控制来源权限矩阵

- [x] REST、Bluetooth、Panel 分别关闭时，对应运动入口被拒绝。
- [x] 关闭一个来源不影响其他已允许来源。
- [x] 全局童锁阻止所有来源启动运动，并立即停止正在进行的运动。
- [x] STOP 不受普通运动来源权限阻塞。
- [x] 权限与童锁在 Gateway 重启后保持，并能安全恢复。

### V1-07 BLE 三客户端与 Bond 管理

测试设备固定为 iPhone、Apple Watch 和 Android 手机。

- [x] 三台设备同时连接并持续收到一致 State、Config 和 Reminder Notify。
- [x] 单一运动所有者生效，其他客户端收到 Desk Busy 且连接保持正常。
- [x] 任意非所有者 STOP 可以立即停止并释放所有权。
- [x] 所有者与非所有者断连行为符合 V1-03。
- [x] 三台在线时 HOLD 续租不因 Wi-Fi 共存而超时。
- [x] 单删在线/离线 Bond、全删 Bond、配对窗口和满额拒绝行为正确。
- [x] 删除 Bond 不淘汰其他设备，重启后列表、别名和客户端类型保持一致。
- [x] REST 或原厂面板接管后，旧 BLE 所有者断连不会停止新的运动来源。

## 4. P1：多端稳定性与发布门禁

### V1-08 移动端与 Watch 稳定性

- [ ] iPhone 连续完成 20 次连接/断开，无需重启手机或 Gateway 即可恢复。
- [x] Android 完成权限、扫描、配对、Notify、Write、后台和异常停止验收。
- [x] Apple Watch 完成扫描、配对、Crown 连续运动、反向和 STOP 验收。
- [ ] 蓝牙关闭、权限拒绝、旧 Bond 冲突均显示明确错误和恢复指引。

### V1-09 BLE/Wi-Fi 自动回退

- [ ] BLE 超距或不可用时，App 只在 REST 可用后切换连接状态。
- [ ] BLE 恢复时不重放旧的 HOLD、档位或 STOP 命令。
- [ ] 切换前后高度、运动状态、配置和自定义档位以 Gateway 回读为准。
- [ ] 运动期间的连接切换符合 V1-03，不产生失控或伪成功状态。

### V1-10 自定义档位与 B12 恢复

- [ ] Web/App 可新增、修改、删除最多 16 个自定义档位并跨端同步。
- [ ] 重启后名称、稳定 ID 和高度保持；不同起点均使用真实高度闭环。
- [ ] 高度未知时拒绝执行自定义档位。
- [ ] B12 无位移看门狗当前关闭；手动 8 秒控制盒重置仍可用。最低/最高边界不误报。
- [ ] REST、BLE 和 Watch 可启动同一条 8 秒控制盒重置序列。
- [ ] 重置期间其他运动被拒绝，STOP 可提前中断，结束后恢复空闲。

### V1-11 OLED 状态显示

- [ ] 高度、侧距和未知状态与 Web 一致。
- [ ] 页面每 4 秒轮播，运动时切换运动页，停止后恢复。
- [ ] ToF 离线有明确告警且不影响 BLE、Web、下降和 STOP。
- [ ] 不接 OLED 时只降级显示，两颗 ToF 和桌控继续工作。
- [ ] OLED 与双 ToF 连续运行 30 分钟，无 Brownout、I2C 超时或闪烁。

### V1-12 移动端发布交付

- [ ] 固件、iPhone、Android 和 Watch 使用同一冻结协议与版本说明。
- [ ] TestFlight 和 Android 内测包完成签名、安装和基础启动验证。
- [ ] 发布说明只声明已经通过本文件验收的能力。
- [ ] 已知限制、恢复方式、局域网使用约束和安全说明已写入发布材料。
- [ ] 发布 commit、构建号和安装包校验信息已归档。

## 5. P2：可选能力门禁

以下能力默认不自动进入 V1。发布负责人必须在验收前选择“纳入 V1”或“不纳入 V1”。

### V1-13 番茄语音提醒

发布决定：`未选择 / 纳入 V1 / 不纳入 V1`

如果纳入 V1：

- [ ] MAX98357A、扬声器、GPIO14/15/16 和 USB 5V 供电完成实物核对。
- [ ] 中文语音清晰，无明显爆音、重复、失真、Brownout 或异常发热。
- [ ] 暂停、继续、跳过、停止、延后、长休息和重启行为符合设计。
- [ ] Web 关闭或 Wi-Fi 断开后，ESP 本地计时和到期播放仍正确。
- [ ] 播放期间 Web、BLE、面板、升降和 STOP 无可感知退化或协议干扰。

### V1-14 小智 AI 端到端

发布决定：`未选择 / 纳入 V1 / 不纳入 V1`

如果纳入 V1：

- [ ] 真实 REST `raise-to-max` 完成幂等触顶、ToF 失效、障碍和 STOP 验收。
- [ ] MCP Bridge、Endpoint、工具注册、认证失败和 Gateway 离线处理通过。
- [ ] “最高”“站立”“坐姿”“停止”使用固定且不同的安全语义。
- [ ] 小智、Bridge 或 Server 退出后，已经开始的运动仍由 ESP32 本地安全闭环停止。
- [ ] 语音失败不回复成功，`started` 不回复“已经到达”。

## 6. P3：明确不属于 V1

以下能力进入后续 backlog，不阻塞 V1，也不得出现在 V1 已交付功能列表中：

- MQTT + Home Assistant；
- Matter、Siri / App Intent、米家和华为生态；

- Loctek、Jiecang 等其他桌型 Driver；
- 原厂档位 2 / 3；
- 原厂“上+下约 5 秒”按键协议逆向；
- BLE OLED / 独立旋钮参考配件。
