# 番茄时钟语音与声音提醒接入方案

| 项 | 内容 |
|---|---|
| 文档编号 | DG-HW-003 |
| 版本 | 0.4 |
| 日期 | 2026-08-15 |
| 状态 | 固件、Web、iPhone/Android 与 Watch 已实现并通过自动化；MAX98357A 与移动真机待验收 |
| 对应阶段 | 健康提醒 / 本地音频 |
| 前置文档 | [ESP32-S3 N16R8 主控选型与开发板说明](../hardware/esp32-s3-n16r8.md) |

本文定义 Desk Gateway 番茄时钟与久坐提醒的第一版产品、音频硬件和软件方案。第一版由 ESP32-S3 独立计时，并通过真正的扬声器播放本地中文语音和普通提示音；即使 Web 页面关闭或 Wi-Fi 暂时断开，也能按时播放。

提醒只产生语音、音效和界面状态，**不得自动驱动升降桌**。当前仓库已经包含提醒组件、I2S 音频驱动、4 MB Audio Data 分区、中文 WAV 资源、REST 接口和 Web 控件，并已用 ESP-IDF v6.0.2 完成隔离构建。GPIO、功放供电、音量、音质、爆音和桌控并行仍必须在 MAX98357A 到货后完成实物验证，因此“代码已实现”不表示语音播放与整机已验收。

### 0.1 当前交付状态（2026-08-15）

| 项目 | 当前结果 |
|---|---|
| 固件构建 | ESP-IDF v6.0.2 隔离构建通过 |
| Factory App | `0x300000`（3 MiB），当前应用 `0x154560`，剩余 56% |
| Audio Data | `audio` SPIFFS，偏移 `0x310000`，容量 4 MiB；完整 `idf.py flash` 自动烧录 |
| 本地语音 | `focus_done`、`break_done`、`snooze_done` 三段中文语音与 `attention_chime` 已生成 |
| 自动化 | WAV/音量、番茄状态机、Web 展示规则及现有仓库测试通过 |
| iPhone / Android | 首页入口、ESP 剩余时间、完整控制、时长/音量/静音/试听已实现；48 项移动端测试通过 |
| Apple Watch | Reminder v1 BLE 状态与 7 个动作、紧凑控制页已实现；15 项 Core 测试和通用 watchOS 构建通过 |

## 1. 方案结论

第一版采用以下完整链路：

```text
ESP32-S3 本地番茄时钟
  └─ 本地 WAV 语音 / 提示音
      └─ I2S TX + DMA
          └─ MAX98357A 数字 Class-D 功放
              └─ 4 Ω / 3 W 全频扬声器
```

核心结论：

- 默认专注 `25` 分钟、短休息 `5` 分钟。
- 每完成 `4` 个专注阶段，进入 `15` 分钟长休息。
- 专注结束播放完整中文语音，例如“专注时间结束啦，起来活动一下吧”。
- 休息结束播放完整中文语音，例如“休息时间结束，准备开始下一轮专注”。
- 普通提示音也作为 WAV 资源播放，可用于前奏、完成音和试听。
- 支持开始、暂停、继续、跳过、停止、延后 `5` 分钟、静音、音量和试听。
- 下一阶段默认由用户手动开始，不在后台静默消耗休息时间。
- 语音和音效存放在独立 Flash 音频分区，不依赖浏览器或互联网。
- 设备重启后倒计时回到空闲态；只恢复用户配置，不恢复未完成阶段。
- 音频子系统异常不得阻止桌控、`STOP`、Wi-Fi、BLE 或原厂面板链路启动。

第一版不包含：

- 到点自动升桌或降桌。
- 云端 TTS、ESP 本地动态中文 TTS 或任意文本合成。
- 手机系统推送和云端同步。
- Web 上传或删除自定义音频文件。
- 每日/每周专注统计。
- 基于墙上时钟的免打扰时段。

第一版使用预先录制并随固件发布的本地语音包。这样可以保证离线可用、播放延迟确定，也不引入云端密钥、隐私和服务可用性问题。

## 2. 产品行为

### 2.1 默认节奏

| 阶段 | 默认时长 | 到期播放 | 后续行为 |
|---|---:|---|---|
| 专注 | 25 分钟 | 专注结束语音 | 等待用户开始休息 |
| 短休息 | 5 分钟 | 休息结束语音 | 等待用户开始下一次专注 |
| 长休息 | 15 分钟 | 休息结束语音 | 等待用户开始下一次专注 |
| 延后 | 5 分钟 | 重复当前到期语音 | 回到等待确认状态 |

专注阶段结束后，已完成专注次数加一。完成次数达到 `4` 的倍数时，下一个休息阶段为长休息，否则为短休息。

默认语音资源：

| 资源 ID | 建议文案 / 内容 | 使用场景 |
|---|---|---|
| `focus_done` | “专注时间结束啦，起来活动一下吧。” | 专注到期 |
| `break_done` | “休息时间结束，准备开始下一轮专注。” | 短休息或长休息到期 |
| `snooze_done` | “休息提醒到了，记得起来走一走。” | 延后到期 |
| `attention_chime` | 短提示音，响度与语音资源接近 | 语音前奏或试听 |

语音文案在录制前可以继续调整，但音频资源 ID 和触发语义应保持稳定，避免界面、测试与具体文件名相互耦合。

### 2.2 状态模型

提醒状态和当前阶段分开表示，避免用一个枚举同时表达“正在专注”和“专注已结束”等不同语义。

| 字段 | 可选值 | 含义 |
|---|---|---|
| `state` | `idle` | 没有活动倒计时 |
| `state` | `running` | 当前阶段正在倒计时 |
| `state` | `paused` | 当前阶段暂停，剩余时间冻结 |
| `state` | `waiting` | 阶段已结束，等待用户开始下一阶段 |
| `state` | `snoozed` | 到期提醒已延后，正在等待再次提醒 |
| `phase` | `focus` | 专注阶段 |
| `phase` | `short_break` | 短休息阶段 |
| `phase` | `long_break` | 长休息阶段 |
| `alarm_reason` | `none` | 当前没有到期提醒 |
| `alarm_reason` | `focus_done` | 专注结束，应站起活动 |
| `alarm_reason` | `break_done` | 休息结束，可继续专注 |

核心状态流：

```text
idle
  └─ start_focus ─> focus/running
                         ├─ pause ─> focus/paused ── resume ─┐
                         └─ 到期 ─> break/waiting <─────────┘
                                           ├─ snooze ─> break/snoozed ─> break/waiting
                                           └─ start_break ─> break/running
                                                                  └─ 到期 ─> focus/waiting
                                                                                  └─ start_focus
```

`stop` 从任何状态回到 `idle`。`skip` 结束当前阶段并进入下一阶段的 `waiting`，但跳过专注不计入“已完成专注次数”。

### 2.3 暂停、延后和播放

- 暂停时保存剩余秒数，继续后以新的单次定时器重新计时。
- 延后只允许在 `waiting` 状态使用，默认延后 `5` 分钟。
- 阶段到期只向音频队列投递一次资源 ID，不得重复创建播放任务。
- 用户执行停止、跳过、静音或新的阶段操作后，应能立即停止当前语音。
- 播放测试音不改变番茄时钟状态，也不影响完成次数。
- 同一时刻只允许一个音频流；新的到期语音可以中止低优先级的试听音频。
- 音频损坏、缺失或播放失败时仍要完成计时状态转换，并在状态中报告音频错误。

### 2.4 重启语义

第一版没有可靠的墙上时钟同步，不尝试在重启后推算原倒计时：

- NVS 只保存专注时长、休息时长、长休息间隔、音频开关、音量和语音包 ID。
- `state`、剩余时间、延后状态和本次会话完成次数只保存在内存中。
- 冷启动后统一进入 `idle`，I2S 和功放保持静音。
- 启动完成前不播放“开机成功”等非必要声音，避免断电恢复时惊扰用户。
- 不得每秒把剩余时间写入 NVS，以免造成不必要的 Flash 磨损。

## 3. 音频硬件方案

### 3.1 器件选择

| 器件 | 推荐规格 | 用途 |
|---|---|---|
| 数字功放模块 | MAX98357A I2S Class-D 模块 | 将 I2S PCM 转换并驱动扬声器 |
| 扬声器 | 4 Ω / 3 W 全频扬声器 | 播放中文语音和普通提示音 |
| 电源 | USB 5V，整机电源预算需复核 | 为功放提供足够瞬态功率 |
| 外壳声腔 | 与扬声器尺寸匹配 | 提高清晰度并避免裸扬声器失真 |

MAX98357A 支持标准 I2S、无需 MCLK，工作电压为 `2.5–5.5 V`；官方数据给出的典型能力是在 `5 V` 供电时向 `4 Ω` 负载输出最高约 `3.2 W`。第一版使用模块而不是裸芯片，仍需确认模块原理图、增益配置、关断脚和去耦器件是否完整。

扬声器不能直接连接到 ESP32-S3 GPIO。MAX98357A 的 `SPK+` 与 `SPK-` 是差分 Class-D 输出，扬声器必须接在二者之间，**任意一端都不得接 GND**。

### 3.2 GPIO 分配

当前已占用或预留的引脚：

| GPIO | 当前用途 / 约束 |
|---|---|
| GPIO4 / GPIO5 | 控制盒侧 CLK / DAT |
| GPIO6 / GPIO7 | 原厂控制面板侧 CLK / DAT |
| GPIO10 / GPIO11 | 双 ToF 传感器预留 I²C |
| GPIO12 / GPIO13 | 双 ToF 传感器预留 XSHUT |
| GPIO19 / GPIO20 | ESP32-S3 原生 USB |
| GPIO35 / GPIO36 / GPIO37 | N16R8 Flash / Octal PSRAM 内部占用，禁止外接 |
| GPIO43 / GPIO44 | UART0 调试 |
| GPIO48 | 板载 WS2812 RGB |

I2S 暂定分配：

| 信号 | GPIO | 说明 |
|---|---:|---|
| BCLK | GPIO14 | I2S Bit Clock |
| LRCLK / WS | GPIO15 | 左右声道 / Slot Select |
| DOUT | GPIO16 | ESP32-S3 到功放的数据 |
| SD / MODE | 暂不占 GPIO | 第一版按模块电阻配置；需要软件硬关断时再评估 GPIO17 |

ESP32-S3 的 I2S 信号可以通过 GPIO Matrix 配置，MAX98357A 又不需要 MCLK，因此第一版只需要三根 I2S 信号线。GPIO14/15/16 必须在接线前确认开发板确实引出，并与 JTAG、启动配置和最终底板原理图复核；当前分配是方案候选，不是已验证 pin map。

建议新增以下 Kconfig：

```text
CONFIG_DESK_REMINDER_ENABLED=y
CONFIG_DESK_AUDIO_ENABLED=y
CONFIG_DESK_AUDIO_I2S_BCLK_GPIO=14
CONFIG_DESK_AUDIO_I2S_WS_GPIO=15
CONFIG_DESK_AUDIO_I2S_DOUT_GPIO=16
CONFIG_DESK_AUDIO_DEFAULT_VOLUME_PERCENT=60
```

### 3.3 接线

![YD-ESP32-S3 与 MAX98357A、扬声器的 I2S 接线（无麦克风）](images/max98357a-wiring.png)

布局对应常见的树莓派 Fritzing 接法：MCU 在左、功放在中、喇叭在右，线色区分 5V / GND / BCLK / LRC / DIN。Desk Gateway 只播放本地 WAV，**不接 SPH0645 麦克风**，也不把 `GAIN` / `SD` 接到 GPIO。

```text
ESP32-S3 / 开发板             MAX98357A                    扬声器
─────────────────            ─────────                    ──────
USB 5V（短接 IN-OUT）或 3V3 ──> VIN
GND ───────────────────────> GND
GPIO14 ────────────────────> BCLK
GPIO15 ────────────────────> LRC / WS
GPIO16 ────────────────────> DIN
                              SPK+ ──────────────────────> +
                              SPK- ──────────────────────> -
```

供电和布线约束：

- 功放优先使用 ESP 开发板 USB 输入侧的 `5V`。YD-ESP32-S3 排针 `5V` 出厂与 USB VBUS 不通（板背 `IN-OUT` 焊盘默认断开），飞线验收可先接 `3V3`（模块允许 2.5–5.5 V）。
- 不能从 GPIO 取电。**不得使用升降桌 RJ45 红线的 3.3V 为功放或扬声器供电。**
- ESP、功放和 USB 电源必须共地。
- 首次接线前确认开发板 `5V` 引脚与 USB VBUS 的实际关系及允许电流。
- 功放附近保留充足去耦；是否增加大容量电容应根据播放峰值时的电压跌落和模块原理图决定。
- I2S 线尽量短，并远离 GPIO4/5/6/7 桌控总线和 ESP 天线。
- 扬声器两根线成对布置，避免 Class-D 开关噪声耦合到桌控信号。
- 初次上电使用低音量和限流电源，确认无异常发热、爆音和 brownout 后再提高音量。

### 3.4 为什么不采用其他方案

| 方案 | 结论 | 原因 |
|---|---|---|
| 有源蜂鸣器 | 不采用 | 只能发固定鸣叫，不能播放真实语音和普通音频 |
| 无源蜂鸣器 + PWM | 不采用 | 只能合成简单音调，不能满足语音需求 |
| 普通扬声器直连 GPIO | 禁止 | GPIO 无法安全驱动低阻扬声器 |
| DFPlayer Mini + microSD | 原型备选 | 接入快，但增加独立解码模块和存储卡，产品一致性与资源管理较差 |
| 云端 TTS | 第一版不采用 | 依赖网络、凭据和外部服务，离线提醒不可靠 |
| ESP 本地动态中文 TTS | 第一版不采用 | 模型、存储、音质和实时性成本明显高于固定提示语需求 |

## 4. 音频资源与 Flash 分区

### 4.1 第一版音频格式

所有第一版资源统一为：

```text
Container: WAV
Codec: PCM signed 16-bit little-endian
Sample rate: 16 kHz
Channels: Mono
```

该格式每秒约占 `32 KB`。一段 5 秒语音约为 `160 KB`，无需引入 MP3/AAC/Opus 解码器，便于验证 I2S、DMA、音量和播放中止逻辑。

构建时必须校验 WAV Header，不接受采样率、位宽或声道数不一致的文件。运行时不做重采样；不符合约束的音频应在构建阶段失败，而不是烧录后静默播放异常。

### 4.2 资源目录

建议目录：

```text
firmware/desk-gateway/audio_assets/
  zh-CN-default/
    focus_done.wav
    break_done.wav
    snooze_done.wav
    attention_chime.wav
  LICENSE.md
  README.md
```

`LICENSE.md` 必须记录每段语音和音效的来源、录制者、生成工具和再分发许可。仓库是公开项目时，不能提交来源不明、商用 TTS 限制再分发或未经授权的声音素材。

### 4.3 独立音频分区

语音不能直接嵌入应用二进制，否则会挤压固件升级空间并让每次改文案都改变应用镜像。建议为 N16R8 的 16 MB Flash 增加自定义分区表：

| 分区 | 建议容量 | 用途 |
|---|---:|---|
| Factory App | 不小于 3 MB | 固件与后续功能增长空间 |
| Audio Data | 4 MB | 只读 WAV 语音包和提示音 |
| NVS / PHY 等 | 按 ESP-IDF 要求 | 配置、校准和系统数据 |
| Reserved | 剩余空间 | 后续 OTA 或其他数据方案评估 |

`4 MB` 音频分区在扣除文件系统开销后，约可容纳两分钟 16 kHz/16-bit/Mono PCM，足够第一版语音包并保留扩展余量。具体偏移、对齐和 Factory App 大小必须以当前构建产物和 ESP-IDF 分区校验结果为准，不能只按表格手工填写。

第一版建议在构建阶段生成只读 Audio Data 镜像，随固件烧录。Web 上传和在线替换语音包留到后续版本，避免第一版同时引入上传鉴权、空间配额、格式转换和断电一致性问题。

## 5. 软件架构

### 5.1 组件边界

`desk_reminder` 只负责番茄状态机；新增独立的 `desk_audio` 负责所有语音和音效播放。二者都不能进入负责运动安全的 `desk_core`：

```text
Web REST ───────────────┐
                       v
                desk_reminder
                ├─ 状态机与参数校验
                ├─ esp_timer 单次倒计时
                ├─ NVS 配置
                └─ 到期事件：prompt_id
                         |
                         v
                    desk_audio
                    ├─ 播放队列与抢占
                    ├─ Audio Data 分区
                    ├─ WAV Header 校验
                    ├─ PCM 音量缩放
                    └─ I2S TX + DMA
```

建议文件结构：

```text
firmware/desk-gateway/components/desk_reminder/
  CMakeLists.txt
  desk_reminder.c
  desk_reminder_logic.c
  include/
    desk_reminder.h
    desk_reminder_logic.h
  test/
    desk_reminder_logic_test.c

firmware/desk-gateway/components/desk_audio/
  CMakeLists.txt
  desk_audio.c
  desk_audio_wav.c
  include/
    desk_audio.h
    desk_audio_wav.h
  test/
    desk_audio_wav_test.c
```

职责约束：

- `desk_reminder_logic` 是不依赖 ESP-IDF 的纯状态机，Host tests 使用假时间验证。
- `desk_reminder` 负责 NVS、并发保护、`esp_timer`、快照和命令入口。
- `desk_audio` 只接受稳定的资源 ID，不理解专注、休息或桌子运动语义。
- `desk_audio_wav` 校验格式并向 I2S 提供 PCM 数据，不做动态格式转换。
- 音频播放任务必须可停止、可静音，且不能阻塞 HTTP Server、Wi-Fi、BLE 或桌控任务。
- 音频或提醒组件初始化失败时记录错误并标记功能不可用，Desk Gateway 其他功能继续启动。

### 5.2 I2S 与播放队列

- 使用 ESP-IDF 新版 I2S Standard TX API 和 DMA，不使用旧版兼容驱动。
- I2S 配置为 `16 kHz`、`16-bit` PCM；Mono 数据按 MAX98357A 的声道选择配置输出。
- 播放任务以小块读取 WAV PCM 并写入 DMA，不把完整音频文件一次性复制到 RAM。
- 软件音量在写入 I2S 前缩放样本，并做饱和处理，避免整数溢出造成爆音。
- 音量 `0` 等价于静音，但设备状态仍记录到期事件。
- 同一时间只允许一个播放实例；每个请求携带代次编号，停止后旧数据不能重新进入 DMA。
- 到期语音优先级高于用户试听；新的到期语音可以中止试听，普通重复请求不叠加。
- 播放前后写入短暂静音帧，并结合模块 SD/MODE 行为验证是否需要额外关断控制，以降低 click/pop。
- 解码、文件系统或 DMA 错误不得回调运动接口。

### 5.3 定时与并发

- 使用 `esp_timer` 单次定时器，不创建每秒更新状态的周期定时器。
- `remaining_sec` 根据单调时钟和截止时间按需计算。
- 定时器回调只投递“阶段到期”事件，不读取文件、不播放音频、不写 NVS、不执行 HTTP 逻辑。
- 独立的提醒任务处理状态转换，再向 `desk_audio` 投递资源 ID。
- 开始新阶段、暂停、停止和跳过时必须取消旧定时器，并丢弃已过期事件。
- 状态更新和快照读取需要明确的互斥边界，防止 Web 请求与到期回调产生双重状态转换。

### 5.4 初始化顺序

音频和提醒都不是运动控制前置条件，因此不得使用会让整个固件退出的强制失败策略：

```text
nvs_flash_init
  → desk_core_init
  → desk_audio_init（失败只降级语音功能）
  → desk_reminder_init（失败只降级提醒功能）
  → BLE / Wi-Fi / Web
```

初始化期间保持 I2S 停止并输出静音。音频分区、WAV 索引或功放不可用时，状态接口应返回具体的不可用原因，而不是假装播放成功。

## 6. 配置与数据模型

### 6.1 配置

| 字段 | 默认值 | 建议范围 | 是否持久化 |
|---|---:|---:|---|
| `focus_minutes` | 25 | 1–180 | 是 |
| `short_break_minutes` | 5 | 1–60 | 是 |
| `long_break_minutes` | 15 | 1–120 | 是 |
| `focuses_per_long_break` | 4 | 1–12 | 是 |
| `audio_enabled` | `true` | 布尔值 | 是 |
| `volume_percent` | 60 | 0–100 | 是 |

### 6.2 运行快照

提醒和音频快照嵌入现有鉴权状态响应，复用 Web 已有的 `/api/v1/desk/status` 轮询，不新增第二个高频请求：

```json
    "remaining_sec": 1234,

```

提醒或音频初始化失败时返回 `available: false` 和稳定的错误原因，页面明确显示降级状态，不伪造倒计时或播放结果。

## 7. REST API

所有提醒和音频接口沿用现有 Bearer 鉴权，不允许未登录访问或修改计时器。

### 7.1 操作接口

```http
POST /api/v1/reminder/action
Content-Type: application/json

{ "action": "start_focus" }
```

第一版动作：

| `action` | 允许状态 | 行为 |
|---|---|---|
| `start_focus` | `idle`、休息结束后的 `waiting` | 开始新的专注阶段 |
| `start_break` | 专注结束后的 `waiting` | 按完成次数开始短休息或长休息 |
| `pause` | `running` | 暂停当前阶段 |
| `resume` | `paused` | 从保存的剩余时间继续 |
| `skip` | `running`、`paused` | 跳过当前阶段并进入下一阶段等待态 |
| `stop` | 非 `idle` | 清空运行状态、停止语音并回到 `idle` |
| `snooze` | `waiting` | 延后 `5` 分钟后再次播放提醒 |

状态不允许的动作返回明确错误，不默默转换为其他操作。重复 `stop` 可以保持幂等并返回成功。

### 7.2 音频操作接口

```http
POST /api/v1/audio/action
Content-Type: application/json

{
  "action": "test_audio",
  "prompt_id": "focus_done"
}
```

第一版音频动作：

| `action` | 参数 | 行为 |
|---|---|---|
| `test_audio` | 已安装的 `prompt_id` | 试听指定语音或音效，不改变计时状态 |
| `stop_audio` | 无 | 立即停止当前语音或试听 |

接口不能接受任意文件路径。`prompt_id` 必须映射到构建时登记的只读资源，避免路径穿越和播放未校验文件。

### 7.3 配置接口

```http
POST /api/v1/reminder/config
Content-Type: application/json

{
  "focus_minutes": 25,
  "short_break_minutes": 5,
  "long_break_minutes": 15,
  "focuses_per_long_break": 4,
  "audio_enabled": true,
  "volume_percent": 60,
  "voice_pack": "zh-CN-default"
}
```

要求：

- 所有数值必须是范围内的整数。
- 缺失字段表示保持原值，便于局部更新。
- 校验失败时不写入任何字段，避免部分成功。
- NVS 写入失败时返回失败，并保留旧配置。
- 未安装的语音包不能被设置为当前语音包。
- 关闭音频或音量归零后立即终止当前播放，但不停止倒计时。

## 8. Web UI

在当前桌控页面增加独立的“番茄时钟”卡片：

- 当前阶段：专注、短休息或长休息。
- `MM:SS` 剩余时间。
- 当前四次循环中的进度。
- 开始、暂停/继续、跳过、停止按钮。
- 到期后的“开始休息”或“开始专注”主按钮。
- “延后 5 分钟”次按钮。
- “语音提醒”开关。
- 音量滑块和当前百分比。
- 专注结束语音、休息结束语音和提示音的独立试听按钮。
- 当前语音包和音频错误状态。
- 时长设置放在现有设置区域，保存后提示“从下一阶段生效”。

页面只根据设备状态渲染倒计时和播放状态，不使用浏览器 Audio 作为提醒来源。前端可以在两次状态响应之间平滑显示剩余时间，但下一次设备快照必须纠正误差。

专注结束语音只提醒用户站起活动，不直接发送升桌命令。页面可以引导用户使用现有“站立”档位按钮，但运动必须来自一次明确的用户操作。

### 8.1 iPhone、Android 与 Apple Watch

iPhone 和 Android 共用 React Native 页面，首页提供番茄时钟入口，详情页展示 ESP 的阶段、剩余秒数和完成次数，并支持：

- 开始专注、开始休息、暂停、继续、跳过、停止和稍后提醒；
- 专注、短休息、长休息和长休息周期配置；
- 语音开关、音量和 `focus_done` 试听；
- App 前后台切换、BLE/Wi-Fi 重连后直接恢复设备快照，不补算手机本地倒计时。

动作可以通过当前 BLE 或 REST 控制通道发送。时长、音量和试听属于管理操作，统一使用已配置的 `X-Desk-Key` REST 通道保存到 ESP；因此手机当前使用 BLE 桌控时，局域网地址和密码仍需可用才能修改这些设置。

Apple Watch 是独立 BLE App，不保存网关地址或 REST 密码。固件新增 UUID `7f4e0008-6d4c-4f4b-9f7a-3c1d2e5a9b10` 的 `Reminder v1` 特征：

- `READ/NOTIFY`：固定 20 字节，包含状态、阶段、剩余秒数、完成次数、提醒配置摘要和语音开关/音量；20 字节可在默认 ATT MTU 下单次发送；
- 加密 `WRITE`：固定 1 字节，只接受 `0x00`–`0x06` 七个提醒动作；
- 旧的 State v1、Config v1/v2、桌控命令和运动所有权规则均不修改；
- Watch 页面只显示 Notify 快照并发送动作，不运行独立 Timer。

## 9. 安全与故障边界

1. **不自动运动。** 到期、延后结束、语音结束或恢复网络都不能触发升降桌。
2. **音频故障不阻塞桌控。** 分区、文件、I2S、DMA 或功放异常不得影响 `STOP` 和现有控制入口。
3. **默认静音启动。** 初始化完成前不播放音频，冷启动和复位不能产生明显爆音。
4. **不用桌子 3.3V 供电。** 功放使用经验证的 USB 5V 电源路径。
5. **扬声器不直连 GPIO。** 必须由合适的功放驱动，差分输出不能接地。
6. **限制音量和播放并发。** 同时只播放一个音频流，默认音量不取最大值。
7. **音频素材可追溯。** 所有语音和音效都要记录授权与再分发条件。
8. **不伪造时间。** 无墙上时钟时不实现免打扰时段、跨重启补算和每日统计。
9. **配置原子更新。** 无效或写入失败时保持上一份完整配置。
10. **过期事件不得生效。** 停止或重启阶段后，旧定时器事件不能再次播放或改变状态。
11. **保持本地边界。** 第一版只沿用现有局域网鉴权，不新增云端依赖。
12. **控制 EMI 和电源扰动。** Class-D 功放、扬声器线和 5V 峰值负载必须经过桌控并行验证。

## 11. 自动化测试要求

- `idle → focus/running → break/waiting`。

- 配置边界值、非整数和部分更新。
- NVS 写入失败时保留旧配置。
- 关闭音频不改变倒计时。

- 接受 16 kHz / 16-bit / Mono PCM WAV。

- 新代次播放可以中止旧播放，旧 DMA 数据不会恢复。

## 12. 真机验收标准

### 12.1 电气与启动

- [ ] 确认 MAX98357A 模块型号、原理图、增益配置和 SD/MODE 行为。
- [ ] 确认扬声器为 4 Ω / 3 W，并正确连接到 `SPK+ / SPK-`。
- [ ] 确认 GPIO14/15/16 在实物开发板上可用且无最终原理图冲突。
- [ ] 确认开发板 5V 路径和 USB 电源能覆盖功放峰值电流。
- [ ] 冷启动、复位和固件升级过程中没有明显爆音或误播放。
- [ ] 功放断开、扬声器断开或音频分区损坏时，桌控仍能正常启动。
- [ ] 连续播放不会导致 brownout、USB 断连或异常发热。

### 12.2 语音与音质

- [ ] 默认音量下，正常办公环境中距离设备 1 米可以清楚听懂全部中文提示语。
- [ ] 最低可用音量没有明显断字，最高允许音量没有持续削波或严重失真。
- [ ] 语音开头和结尾完整，不吞字、不重复、不出现明显 click/pop。
- [ ] 专注结束、休息结束和延后结束播放正确资源，不串音。
- [ ] 试听可以立即停止，到期语音可以中止正在播放的试听。
- [ ] 语音关闭或音量为 0 时不发声，但倒计时和到期状态仍正确。
- [ ] 机壳和安装位置不会遮挡扬声器，也不会产生不可接受的共振。

### 12.3 计时行为

- [ ] 设置 1 分钟专注，关闭 Web 页面后仍只在到期时播放一次完整语音。
- [ ] 暂停至少 30 秒后继续，实际到期误差目标不超过 `±1 秒`。
- [ ] 停止、跳过和延后不会出现旧定时器二次播放。
- [ ] 第 4 次完成专注后进入长休息等待态。
- [ ] 重启后回到 `idle`，配置保留，但不会补播重启前的提醒。

### 12.4 与桌控并行

- [ ] 播放期间 Web、REST、BLE 和原厂面板状态更新正常。
- [ ] 播放期间升、降和 `STOP` 响应时间没有可感知退化。
- [ ] GPIO4/5/6/7 协议链路没有新增错误、丢帧或时序异常。
- [ ] 扬声器和 I2S 线不会给高度数据或面板链路引入可复现干扰。
- [ ] Wi-Fi 临时断开不影响 ESP 上的倒计时和本地语音，重连后页面恢复正确状态。
- [ ] 语音到期不会自动调用升桌、降桌或档位动作。

### 12.5 移动端与 Watch

- [ ] iPhone 和 Android 通过 BLE、Wi-Fi 两种连接分别完成开始、暂停、继续、跳过、停止和稍后提醒。
- [ ] 手机退到后台至少 30 秒再回前台，显示值以 ESP 回读为准，没有第二个本地倒计时漂移。
- [ ] 手机通过 REST 修改时长、静音和音量后，Web、BLE 手机和 Watch 都收到同一设备状态。
- [ ] Watch 可以读取 Reminder v1、执行七个动作，且番茄操作不会进入桌体运动命令队列。
- [ ] 手机与 Watch 同时在线操作番茄时钟时，ESP 状态机拒绝非法动作，客户端不伪造成功状态。
- [ ] 旧固件缺少 Reminder 特征时，原有手机和 Watch 桌控仍可使用，并明确显示番茄功能不可用。

只有通过以上验收，功能状态才能从“代码已实现”更新为“语音播放与整机已验证”。
